# netshare

Console controller. `netshare` is the entry. `lib/tunnel.sh` is the tun,
routing, and DNS. `lib/bar.sh` is the optional panel readout (`netshare bar`)
and is not on the path that brings the tunnel up. `bar/netshare.qml` is an
optional Omarchy module. tun2proxy is the data plane and is not vendored.
Depth is the script header and [README.md](README.md). Do not paste local
design notes into this repo.

## Hard constraints

- Do not commit live command output, logs, `/etc/netshare.conf`, or `/run/netshare/`. `netshare status` and `netshare bar` print the live SSID, interface, and addresses.
- Do not add SSIDs, BSSIDs, MAC addresses, interface names, hostnames, search domains, or a home LAN prefix. The `192.168.49.0/24` mapping in the script is the NetShare app's own addressing.
- Do not hardcode an interface or an SSID. Discovery is the gateway proxy. `CONNECTION_PREFIX` applies only to `bar`. `up` and `status` still consider every connected link.
- `up` does not require a desktop session. With `SUDO_UID` or `NETSHARE_UID`, that account's traffic follows the tun. With neither, the tun stays in side posture for `netshare run` and the host resolver stays as it was. Do not turn a missing uid back into a hard error.
- Never pass tun2proxy `--setup`. No `/1` routes. Do not use `198.18.0.1` as a resolver. Do not `resolvectl revert` a NetworkManager link that still has DHCP DNS.
- Posture values are `desktop` and `side`.
- A bar-module edit needs `omarchy restart shell`, and only when the user asks. Do not edit `/usr/share/omarchy`. Do not `omarchy refresh shell`.
- Do not click the bar switch or inject pointer events. Do not run `up` or `down` unless the user asks.
- Do not elevate with `sudo -n` when a password is required. A cached ticket may skip the prompt. A terminal prompts on the terminal. No terminal, and the bar (`NETSHARE_PROMPT=desktop`), uses the desktop askpass helper. Do not add a NOPASSWD rule for netshare.
- Do not change git config.

## Checks

`bash -n netshare` after a script edit. `bash test/run.sh` runs the fixture tests. Those tests must not call `up` or `down`, and their fixtures stay on synthetic names. `netshare bar` is read-only and its output stays out of the commit.

The installed NetworkManager dispatcher is generated by `up` with this machine's controller path. The repo file `netshare-dns-dispatcher` must not grow an absolute home-directory path.
